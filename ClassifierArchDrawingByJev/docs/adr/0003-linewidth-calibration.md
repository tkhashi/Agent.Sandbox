# ADR 0003: 線幅(linewidth)の解釈ズレをPDFごとに自動キャリブレーションする

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

抽出したベクター線をSVGに再描画したところ、線の太さが原本と一致しなかった。調査の結果、pdfplumber(内部的には`pdfminer.six`)が`page.lines`/`page.curves`で報告する`linewidth`属性が、`page.to_image()`(pypdfium2による実際の描画結果)と比較して系統的に太い値になっていることが実測で判明した。

検証方法: `page.to_image(resolution=200)`で得たラスタ画像と、抽出したベクターデータをそのままSVG化し同一DPIでラスタライズした画像を、Pillowで同一ピクセル座標の水平/垂直スキャンラインを取り、連続する黒画素のラン長(px)を実測して比較した。

- 図面外枠線(`linewidth=11.5`): 実測される黒画素の連続幅は4px(200dpi換算で約1.44pt相当)。比率は約8倍
- 壁の二重線や扉記号などの近接した複数線でも、報告値をそのまま使うと本来離れて見えるはずの線同士が重なり合い、密集部分が塗りつぶされたように見える不具合を確認

最初はこの場しのぎとして、`render.py`に`_LINEWIDTH_CALIBRATION = 1/8`というハードコードされた補正係数を追加して対処した。しかしこれは今回のPDF・CADエクスポータ固有の値を決め打ちしているだけであり、別のPDFでは通用しない対症療法だったため、ユーザーから「汎用的にプログラムで解決してほしい」という指摘を受けた。

## 決定

`page.to_image()`の実際の描画結果を「正解」とみなし、抽出したベクターデータの`linewidth`メタデータと突き合わせて、**PDFごとに自動でスケール係数を導出する**キャリブレーション処理(`calibration.py`の`calibrate_linewidth`)を実装した。

- サンプル選定: 他のオブジェクトと重なっていない「孤立した直線」を、報告`linewidth`の値ごとに層化サンプリングして選ぶ
  - 長さ閾値・孤立判定の余白は固定のpt値ではなく、ページ対角線や線分自身の報告linewidthから相対的に算出する(絶対値の決め打ちを避けるため)
  - 最低限必要なサンプル数も固定値ではなく、報告linewidthのdistinct値の種類数から算出する
- 各サンプルについて、ラスタ画像上で線分に垂直な方向にスキャンし、黒画素の連続幅(px)を実測してpt換算し、報告値との比を求める
- 複数サンプルの比を中央値+MAD(median absolute deviation)で外れ値除去した上で、頑健な代表値をスケール係数として採用する
- サンプル不足・測定失敗時は安全側に`scale=1.0`(無補正)にフォールバックする
- CLIには`--linewidth-scale`(手動指定)と`--no-linewidth-calibration`(無効化)を用意し、自動判定を上書き・無効化できるようにした

## 理由

- 通常のPDF(報告値と実測が一致するケース)では、サンプルの比が1.0付近に集まり自動的に`scale≈1.0`になるため、この仕組みを常に適用しても無害である
- 本PDFに対して自動実行した結果、`scale≈0.18`を検出し、手動で導出した経験値`1/8=0.125`と近いオーダーの値であることを確認した(完全一致ではないが、外枠線・壁の二重線・扉記号周辺の実測太さは原本とほぼ一致する水準まで改善した)
- サンプル選定基準を絶対値の決め打ちにせず、ページ寸法やデータ自身の分布から導出することで、ページサイズやCADエクスポータが異なる別のPDFでも同じロジックが機能するようにした

## 影響

- `render.py`から`_LINEWIDTH_CALIBRATION`のハードコード定数を削除し、`build_svg(..., linewidth_scale=...)`として呼び出し側から係数を渡す形に変更した
- `pyproject.toml`の`dependencies`に`pillow`を明示的に追加した(画素解析で直接importするため)
- 中間データJSON(`extract.py`が出力する`linewidth`フィールド)自体は生値のまま(未補正)。補正はSVG描画時にのみ適用される。分類ロジックで`linewidth`を特徴量として使う場合は、このキャリブレーション結果を別途考慮する必要がある
