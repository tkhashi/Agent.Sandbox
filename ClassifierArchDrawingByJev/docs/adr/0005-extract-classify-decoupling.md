# ADR 0005: 抽出タスクと分類タスクを疎結合にし、抽出JSON出力形式を変更する

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

ここまでは「PDF→ベクター中間データ抽出→SVG再描画」という抽出タスクのみを実装してきた。ここから、抽出済みデータを解釈して図面要素(通り芯・寸法線・壁中心線など)を分類する「分類タスク」に着手するにあたり、ユーザーから「抽出タスクと分類タスクはコード上疎結合とし、それぞれ別途実行できるよう設計する」という明示的な要件が出された。

分類タスクのSVG再描画(検出結果を`#ff4500`等の色でハイライトした再現SVG)には、ページ幅・高さと線幅キャリブレーション係数(ADR0003参照)が必要になる。しかし、既存の抽出タスクのJSON出力(`-o`オプション)は`list[VectorRecord]`のフラットな配列のみであり、これらのページメタ情報を含んでいなかった。

## 決定

- 分類ロジック(新規`classify`パッケージ)は`schema.VectorRecord`という**データ型のみ**に依存し、`extract.py`・`pdfplumber`・PDFファイルには一切依存しない設計にする。分類タスクの入力は、抽出タスクが出力したJSON(または`list[VectorRecord]`)のみで完結させる
- 抽出タスクのJSON出力形式を、`list[VectorRecord]`のフラットな配列から、`{"page_width": ..., "page_height": ..., "linewidth_scale": ..., "records": [...]}`というオブジェクト形式に変更する(既存フォーマットへの破壊的変更)
- `-o`(JSON出力)または`--svg`(SVG出力)のいずれかが指定された場合は、常に線幅キャリブレーションを実行し、結果をJSONに含める(従来は`--svg`指定時のみ実行していた)
- SVG再描画(`render.py`の`build_svg`)に、「どのレコード(インデックス)をハイライト色にするか」という汎用的な`highlight_indices`/`highlight_color`パラメータを追加する。「通り芯」のような分類概念を`render.py`自体には持ち込まず、分類タスク側(`classify_cli.py`)がハイライト対象のインデックス集合を決めて渡す
- CLIエントリポイントも既存の`extract-vectors`とは別に、新規`classify-grid-lines`を`pyproject.toml`に追加し、それぞれ独立に実行できるようにする

## 理由

- 分類タスクがPDFファイルやpdfplumberに依存しないことで、抽出処理(重い・PDFパーサのバージョン依存がある)と分類処理(軽い・純粋なデータ処理)を完全に独立してテスト・実行・デプロイできるようになる
- ページメタ情報とキャリブレーション係数をJSONに含めることで、分類タスクがPDFを再度開かなくても、抽出タスクと同じ見た目でSVGを再現できる
- `render.py`にハイライト機能を汎用的なインデックスベースの仕組みとして実装することで、将来「寸法線」「壁中心線」等の別の分類カテゴリを追加する際も同じ仕組みを再利用できる

## 影響

- 既存の抽出JSON出力を読む既存のスクリプト・ツールがあれば、新しいオブジェクト形式(`records`キー配下にレコード配列がある)への追随が必要になる。現時点では本プロジェクト内で完結しているため影響は無い
- `src/classifier_arch_drawing/cli.py`と`render.py`を変更し、`classify/`パッケージと`classify_cli.py`を新規追加した
