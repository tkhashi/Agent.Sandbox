# ADR 0004: 文字の位置・回転・フォントサイズはmatrixから直接導出する

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

SVG再描画したテキストに3つの不具合が見つかった。

1. 斜めに描画された文字列(例:「隣地境界線」)が、原本では斜めの一続きの文字列なのに、SVGでは一文字ずつ水平に並び、文字列全体としてのみ斜めに見える
2. 通り芯番号(`X1`/`X2`/`Y1`/`Y2`等)の描画位置が、原本では円の中央なのに、SVGではわずかにズレている
3. 縦方向に記載された寸法数字が、原本では横向きの文字が回転して縦に並んでいるのに、SVGでは一文字ずつ水平のまま縦に並んでしまう。また縦書きの文字だけフォントサイズが原本と異なる

原因調査のため、pdfplumberの`page.chars`が持つ`matrix`(文字の変換行列 `(a,b,c,d,e,f)`)を実データで確認した。

- 斜め文字「隣地境界線」: `matrix=[3.1029, 6.3619, -6.3619, 3.1029, ...]`。回転角`atan2(b,a)≈64°`。同じ文字列が別の場所にもう一組あり、そちらは`matrix=[6.1601,-3.4852,3.4852,6.1601,...]`で回転角は異なるが`スケール=sqrt(a²+b²)≈7.078`は一致する。ところが両方とも`size`フィールドはそれぞれ`9.46`・`9.65`で一致せず、matrix由来の真のスケール(7.078)とも一致しない
- 縦書き数字(例:「8,400」の「8」): `matrix=[0.0, 7.08, -7.08, -0.0, ...]`(90°回転、スケール7.08)。隣接する非回転文字は`matrix=[7.08,0,0,7.08,...]`で同じ7.08。しかし縦書き数字の`size`フィールドは`3.54`と、真のスケールのちょうど半分になっている
- `X1`/`Y1`等の非回転文字: `matrix`の並進成分`e`は`x0`と一致するが、`f`をpage.heightから変換した値(真のベースライン位置)は、バウンディングボックス下端`bottom`と約1.2pt(フォントサイズの約14%)ずれている(フォントのディセンダ分の差)

この3つの不具合はすべて、「バウンディングボックス由来の`x0`/`bottom`/`size`だけを使い、回転を考慮せずに水平配置している」という同一の実装上の原因に起因することが判明した。加えて`size`フィールド自体が、回転した文字(`upright=False`または回転行列を持つ文字)に対してpdfminer.six側で不正確な値になる(検証したケースではちょうど半分になる)ことも実データで確認した。

## 決定

文字の描画位置・回転・フォントサイズを、すべて`matrix`から直接導出する方式に統一する。バウンディングボックス由来の値には依存しない。

- 有効フォントサイズ: `font_size = sqrt(a² + b²)`
- 回転角(SVG用、度): `rotation_deg = -degrees(atan2(b, a))`(PDFのY-up座標系からpdfplumberのY-down(top-down)座標系への変換に伴う符号反転。斜め文字・縦書き数字の実測値から、この符号規則で正しい向きになることを検証済み)
- 描画位置: `x = e`, `y = page_height - f`
- SVG出力: `<text x="{x}" y="{y}" font-size="{font_size}" transform="rotate({rotation_deg} {x} {y})">`
- `matrix`が取得できない場合のみ、従来通り`x0`/`bottom`/`size`・回転なしにフォールバックする

## 理由

- 3つの不具合が同一原因に起因していたため、個別に対処療法を当てるのではなく、根本原因(matrixを無視していたこと)に対して1つの一般的な修正を行う方が保守性が高い
- `size`フィールドが回転文字で信頼できないことを実データで確認したため、`matrix`から直接スケールを再計算する方式は、この不具合にも同時に対応できる
- 実PDFで検証した結果、斜め文字・縦書き数字とも原本とほぼ完全一致する見た目が得られた。`X1`/`Y1`等の通り芯番号も円の中心に近い位置に改善された

## 影響

- `schema.py`の`VectorRecord`に`matrix`フィールドを追加し、`extract.py`の`_normalize_char`で`obj.get("matrix")`を保存するようにした
- `render.py`に`_char_transform`ヘルパーを追加し、`_record_to_svg_element`のchar分岐を書き換えた

## 保留事項

`X1`/`Y1`等の位置ズレの一部(完全な一致にはならない残差)は、SVGが実際の埋め込みフォント(`AAAAAB+font0000000030638abc`)ではなく代替フォント(`font-family="sans-serif"`)で描画しているために生じる、グリフごとの字形・字送り幅の違いによるものと考えられる。これはフォント埋め込み対応が必要な別種の問題であり、ユーザーの指示により今回は対応を保留し、別タスクとして扱う。
