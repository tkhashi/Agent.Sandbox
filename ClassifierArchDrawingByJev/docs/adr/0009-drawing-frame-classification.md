# ADR 0009: 図面枠・図面メタ情報は「最外周の同一線種長方形」と「それに接する区画線」で判定する

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

通り芯・寸法線・壁に続き、図面枠(用紙全体を囲む枠線)と図面メタ情報(表題欄: 案件名・スケール・図面番号等を記載する領域)を分類する要件があった。ユーザーからの要件:

- ページの最外周にある、一続きの同一線種(線幅)の直線でできた長方形があれば、それが図面枠である
- 図面枠には必ず下部に案件名・スケール・図面番号等を記載する領域があり、その領域と図面本体の領域は直線で分割されている
- 図面枠に接した直線があれば、それも図面枠である(ただし軸並行(X/Y方向)の場合に限る)
- こうしてできた図面枠の内側のうち、区画線で区切られた領域の一部が「図面」、それ以外が「図面メタ情報」
- 出力は図面枠・図面メタ情報のいずれも`#ff00ff`で着色する(単色、スコアやグラデーションは不要)

実データ(`resouces/設計図-2階平面詳細図.pdf`)を調査した結果、線幅11.5ptの直線が5本存在し、そのうち4本(水平2本・垂直2本)がページのほぼ全体を囲む長方形(x: 30.8〜1153.3、y: 26.0〜816.9)を構成し、残り1本(y=774.4、x: 30.8〜1153.3の水平線)がその長方形の左右両辺に接し、下部の表題欄(y: 774.4〜816.9)と図面本体(y: 26.0〜774.4)を分割していることを確認した。

## 決定

### 1. 図面枠の外枠検出

軸並行の`line`を線幅ごとにグループ化し、同一線幅の水平2本+垂直2本が閉じた長方形(4辺の座標が一致)を構成する組み合わせのうち、**面積最大**のものを図面枠の外枠とする(`_find_frame_rectangle`)。「最外周」を絶対座標ではなく「面積最大」という相対的な基準で表現し、他のPDFでも通用する汎用的な判定にする。

組み合わせ爆発を避けるため、候補となる直線はページ寸法の50%以上のスパンを持つものに限定する(`_MIN_BORDER_SPAN_RATIO`)。図面枠は定義上「最外周」の線であり、ページの大部分を占める長さを持つはずなので、これ未満の短い線分を候補から除外しても図面枠の検出漏れにはならない。

### 2. 図面枠に接する直線の収集

外枠の4辺いずれかに端点が乗っている(点-線分距離が許容値以内)軸並行の`line`を、すべて「図面枠」に属するものとして収集する(`attached_line_indices`)。方向は水平・垂直のみを対象とし、斜めの線は対象外とする(ユーザー要件の「XY方向の場合に限る」を反映)。

この判定は文字通り「外枠に接しているか」だけを見るため、意匠的に外枠の角に接する装飾要素(方位マークの枠等)も対象に含まれうる。これは意図した動作である(下記「既知の制約」参照)。

### 3. 図面/図面メタ情報の領域分割

外枠に接する直線のうち、外枠の全幅または全高にわたって伸びるもの(区画線)を使い、外枠の内側を格子状に分割する。分割後の領域(セル)のうち**面積最大のもの**を「図面(本体)」、それ以外を「図面メタ情報」とする。

「最大面積=図面本体」という判定は、表題欄が通常、図面本体よりも大幅に小さい帯状の領域として配置される、という建築図面の一般的な慣行に基づく。半径・絶対pt値のハードコードを避け、相対的な基準(面積比較)で判定する方針(ADR0003以降踏襲)に沿っている。

区画線が外枠全体ではなく一部の領域(表題欄内部の列区切り等)にしか及ばない場合は、格子分割の対象に含めない(全幅/全高を条件とすることで自動的に除外される)。そのため、表題欄内部のさらなる列区切りは個別に領域分類されず、表題欄全体が一括して「図面メタ情報」として扱われる。

### 4. 図面メタ情報に属するレコードの判定

各`VectorRecord`の中心座標(`record_center`)が、メタ情報として判定されたセルの範囲内にあるかで判定する(`meta_record_indices`)。対象は`line`に限らず、`char`・`curve`・`rect`等すべてのオブジェクト種別を含む。

## 理由

- 「最外周の同一線種長方形」を絶対座標ではなく「同一線幅グループ内で面積最大」という相対的な基準にすることで、ページサイズ・図面枠の位置が異なる別のPDFでも通用する
- 「図面枠に接した直線は図面枠である」というユーザー要件を、点-線分距離による単純な接触判定として素直に実装した。再帰的に(区画線に接する別の線も図面枠とみなす、等)拡張することも考えられるが、実データでは表題欄内部の列区切り線がたまたま外枠の下辺に直接接していたため、単純な単段階の接触判定だけで表題欄全体を正しく分割できた。再帰化は不要な複雑化と判断し見送った
- 図面/メタ情報の判定も「最大面積セル=図面」という相対基準にすることで、表題欄が上下左右どこに配置されていても(本PDFでは下部だが)同じロジックで対応できる

## 既知の制約

- **装飾要素が偶然図面枠に含まれる**: 本PDFでは、左上の方位マーク(コンパス)を囲む矩形の上辺・左辺が、たまたま図面枠の外枠と同じ座標(角が一致)にあり、「外枠に接する直線」として図面枠に含まれた。これは要件を文字通り実装した結果であり誤りではないが、意匠的な要素が意図せず図面枠として着色される可能性がある。図面枠と図面メタ情報を同色(`#ff00ff`)で出力する現状の要件では実害はないが、将来「図面枠(外枠そのもの)」と「それに接する装飾要素」を区別する必要が出てきた場合は、別途フラグを設けるなどの拡張が必要になる
- **格子分割は単純な行×列の直積のみ**: 区画線が「全幅」または「全高」にわたる場合のみを対象とするため、L字型・階段状など複雑な形状の表題欄配置には対応できない可能性がある(本PDFでは単純な水平1本の区画線のみで正しく動作することを確認済み)
- **複数ページPDF・斜め方向の図面枠は未対応**: 既存タスクと同様の制約
