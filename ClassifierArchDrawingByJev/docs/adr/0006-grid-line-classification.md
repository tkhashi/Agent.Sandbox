# ADR 0006: 通り芯・通り芯番号は「円+ラベル」と「共線クラスタ」の組み合わせで判定する

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

分類タスクの第一弾として、通り芯(グリッド線)と通り芯番号(丸囲みラベル)を分類する必要があった。ユーザーからの要件は以下の通り:

- 通り芯番号は必ず番号を持ち、その番号は数字/アルファベット(またはその組み合わせ)であることが多い
- 通り芯番号の中央方向に通り芯が伸びている
- 通り芯番号は数字、もしくはアルファベットによる連番である
- 通り芯同士の間には必ず寸法線とその寸法が記載されている

実PDF(`resouces/設計図-2階平面詳細図.pdf`)の抽出済みデータを直接調査し、以下を確認した。

- 通り芯番号の丸は`curve`オブジェクトで、点列(`pts`)の重心からの距離のばらつきが小さい、ほぼ真円の閉じたポリゴン(実測: 半径≈8.5pt、186〜187点)
- 円の中心付近に1〜2文字の`char`が存在し、連結すると"Y2"や"X1"のようなラベルになる
- 通り芯そのものは、円の中心座標と**ほぼ完全に一致する**(実測差0.03〜0.2pt程度)座標を共有する、**多数の短い`line`セグメントの集合**である(一点鎖線がPDFエクスポート時に複数の短い実線として展開されているため)。実測ではY2ラベルの水平線が106本(x=120〜1051)、X1ラベルの垂直線が39本(top=60〜761)存在した

### 誤検出の検証

「円に見えるcurve」を単純な閉ループ判定(点列の重心距離の相対標準偏差が小さいこと)だけで全curveから抽出したところ、本PDFでは30件ヒットしたが、真の通り芯番号(半径≈8.5pt)は4件のみで、残りはドア把手・水栓アイコン・方位マーク等の装飾的な小さい円(半径2〜10.2pt、不揃い)だった。

## 決定

半径のような絶対値を閾値としてハードコードせず、以下の2条件を**両方**満たすものだけを「通り芯番号+通り芯」として確定する。

1. 円の中心近傍に、`^[A-Za-z]{0,3}[0-9]{0,3}$`にマッチする(非空の)ラベルテキストを構成する`char`が存在する
2. 円の中心と同じ座標(水平ならy、垂直ならx)を共有する`line`が、規定本数(既定5本)以上、かつページ寸法に対して十分な範囲(既定: 該当軸のページ寸法の10%以上)にわたって存在する

さらに、確定した通り芯番号のラベルテキストをアルファベット接頭辞と数値部分に分解し(`^([A-Za-z]*)([0-9]*)$`)、同じ接頭辞を持つラベル間で数値部分が重複していないかを`sequence_plausible`として記録する。ただしこれは診断用の付加情報であり、判定のフィルタ条件としては使わない。

## 理由

- 半径だけで閾値を決め打ちすると、フォントサイズや図面スケールが異なる別のPDFで通用しない対症療法になる(ADR0003で線幅キャリブレーションについて学んだ教訓と同じ)。「妥当なラベルテキストの存在」と「対応する長い共線クラスタの存在」という2条件の組み合わせは、装飾的な円(ラベルが無い、または対応する長い線が無い)を自然に除外でき、より汎用的な判定になる
- 実データで検証した結果、この2条件だけで誤検出無く`X1`/`X2`/`Y1`/`Y2`の4本すべてを正しく検出できた
- 「連番であること」はユーザーが明言した通り芯番号の性質だが、これを判定の必須条件(ハードフィルタ)にすると、連番の一部だけが検出漏れした場合に他の正しい検出結果まで巻き込んで棄却してしまうリスクがある。そのため診断用の情報として記録するに留めた
- 寸法線との位置関係(「通り芯同士の間には必ず寸法線とその寸法が記載されている」)は、今回の判定には利用していない。通り芯番号+共線クラスタの組み合わせだけで十分な精度が得られたため、寸法線を分類する後続タスクでの検証材料として温存する

## 追記(2026-09-23): 「共線クラスタの本数・スパン統計」から「本物の交互リズム検出」へ

寸法線分類(ADR0007)で、たまたま同じ座標・同じ線幅の単発の直線が「一点鎖線クラスタ」に誤って混入する問題が実データで見つかった。原因は、`find_collinear_cluster`が「集めた線分の本数・スパン」という**集合レベルの統計**だけで一点鎖線を判定しており、**個々のメンバーが実際に長短交互のリズムを構成しているか**を検証していなかったことにある。

このため、`find_collinear_cluster`(座標一致+線幅多数決)を`find_chain_runs`(座標一致+線幅グループ化+**長短交互リズムの実地検証**)に置き換えた。通り芯も寸法伸長線と同じ一点鎖線であるため、この変更は本ファイル(`grid.py`)にも適用される。詳細なアルゴリズムと実データでの検証結果は`docs/adr/0007-dimension-line-classification.md`の該当追記を参照。

`classify_grid_lines`では、ラベル円の軸・座標に対応する有効なラン(`find_chain_runs`の戻り値)をすべて合算し、合算後のスパンが通り芯としての規模(ページ寸法比10%以上)を満たすかで最終判定する。通り芯が無関係な線によって分断され複数のランになっていても、それらを合算することで1本の通り芯として扱える。

## 影響

- `src/classifier_arch_drawing/classify/grid.py`に`classify_grid_lines`を実装した。定数(`_CIRCLE_RELATIVE_STD_MAX`, `_MIN_CLUSTER_SEGMENTS`, `_MIN_SPAN_RATIO`等)は経験的な閾値であり、他のPDFで検出漏れ・誤検出が起きた場合はこれらの値を見直す必要がある
- 現状は1ページ・水平/垂直の通り芯のみを対象としている。斜めの通り芯や複数ページへの対応は将来の拡張点として残っている
